# **数字记忆相框（患者端） PRD（MVP 开发版）**

* **文档版本**：v1.3.0（含前端拟物化与演示架构集成版）  
* **日期**：2026-09-03  
* **产品名称**：数字记忆相框（患者端）  
* **一句话定位**：面向阿尔茨海默病患者的浏览器全屏 Web 应用——以“老街坊数字人相框”形态提供云端零操作冷启动、怀旧陪聊、无感认知活力参考监测与日落舒缓干预。  
* **赛事对标**：AIx Origin Summit 2026 · Vital 活域赛道。对齐评审五要素：真实痛点 / 专业融合 / 可演示闭环 / 免责与伦理 / 落地思考。

## **1\. 产品概述**

### **1.1 背景与真实痛点**

* 中国 60 岁以上人群中阿尔茨海默病患者约 1000 万，其中轻中度患者绝大部分居家照护。  
* 核心痛点：家属照护压力大、缺乏沟通方法（不敢聊、不会聊）；患者对“AI 助手”有距离感。  
* 本系统定位为**非临床的陪伴与干预工具**：不做诊断、不替代医嘱。

### **1.2 目标用户**

* **直接用户**：阿尔茨海默病患者。默认**不具备阅读与配置能力**：全流程零文字输入、操作 \<= 2 次点击，配置责任完全移交家属端（云端下发）。  
* **演示受众**：Vital 赛道评委（评审偏好数字弱势群体、3 语（普通话、粤语及英语）适配、有边界的陪伴）。

### **1.3 运行载体**

* 浏览器全屏 Web（iPad / PC，Safari / Chrome）。  
* 依赖设备前置摄像头（眼动追踪）与麦克风（声学采集、ASR），首次进入需授权。  
* 部署形态：演示时笔记本电脑做网页 UI 相框外壳模拟。

### **1.4 技术底座**

| 能力 | 技术 | 说明 |
| :---- | :---- | :---- |
| 眼动/视线追踪 | MediaPipe FaceMesh（浏览器端） | 定位 468 个面部关键点中的虹膜中心（468/473），判断注视落点；本地计算，不上传视频 |
| 声学特征 | Web Audio API（浏览器端） | 本地实时计算停顿潜伏期、语速、停顿比率、音量包络；不上传原始音频 |
| 对话引擎 | 后端 FastAPI \+ LLM（GLM5.3flash（暂定，可更换模型）） | 验证疗法 Prompt 路由，角色双层体系见第 3 章 |
| 语音 | 粤语 / 普通话 / 英语 ASR \+ TTS | TTS 语速 0.85x；命中人物语音样本时使用零样本克隆音色（见 3.3） |
| 声音克隆 | 零样本克隆（OpenVoice v2 / CosyVoice 零样本模式） | 数秒参考音频克隆音色，CPU/低配 GPU 可跑；不做微调训练（现场不可控） |
| 照片活化 | LivePortrait（预生成） | 单张照片生成“待机微动视频”（眨眼、轻微点头），预生成规避实时延迟 |

### **1.5 MVP 功能范围**

**纳入（P0）**：云端配置冷启动与设备绑定、待机老照片轮播、验证疗法双语对话（含照片亲人模式与声音克隆）、眼动/声学认知活力参考指标采集、日落综合征舒缓模式、双端真实上传 Demo 闭环。

**不纳入（范围外，见第 14 章）**：40Hz 声波刺激（原 GAMMA 模式全面剔除）、待机定时主动搭话、注视唤醒/待机人体感应、生物标志物调试视窗入主界面（改为隐藏 URL 参数）、独立老歌播放器（老歌仅作舒缓模式内容源）、实时口型数字人、医生端、家属端界面（仅定义接口契约）、真实硬件相框。

### **1.6 成功标准**

1. 家属端注入“海珠桥修自行车”记忆后 1 分钟内，患者端数字人能在对话中自然引用该记忆。  
2. 时空错位话术（“我要去上班”）获得顺应式安抚而非纠错。  
3. **双端真实上传 Demo 闭环**（见 F-P05）：全程无预置旁路数据，评委现场看着家属端上传 \-\> 患者端“长出”内容。

## **2\. 冷启动价值与个性化分层**

### **2.1 记忆分层金字塔**

L3 交互偏好层    \-- 眼动热力/高共鸣话题/对话风格，越用越懂老人（自动积累）  
L2 个人记忆层    \-- 家属语音留言/照片/口述史/声音样本注入（冷启动后持续生长）  
L1 公共时代记忆层 \-- 冷启动资产包（绑定时按 地区 \* 年代 \* 语言 即刻就位）

### **2.2 冷启动的价值论证**

* **冷启动是“第 0 天的地板”，不是天花板**：没有它，相框通电时是空壳——说不出老人听得懂的话题、放不出他年代的歌，家属第一印象就是“没用”，产品死于首次体验。冷启动保证**开箱即有 60 分**。  
* **个性化是持续上升的电梯**：家属每注入一条记忆，L2 权重上升；冷启动的 L1 内容**永不删除**，退居为“共同语言背景”——数字人聊海珠桥（L2 个人记忆）时，用的正是 80 年代广州（L1 公共背景）作为语境。L1 让 L2 说得“像那个年代的人”。

## **3\. 对话角色体系（双层角色）**

**核心原则：AI 永不以“AI/助手/机器人”身份出现在患者面前。** 后台 LLM 引擎始终隐身，仅通过“角色外壳”与老人对话（验证疗法的情感真实性要求）。对家属端的伦理披露策略见第 11 章。

### **3.1 第 1 层：常驻角色「老街坊」**

* 固定插画形象（呼吸微动动效）+ 固定名字（默认“强叔”，家属端可改名）。  
* 口吻设定为老人同龄街坊/故友，负责日常搭话、怀旧话题、日落安抚。  
* 无照片触发时，一切对话在该角色下进行。

### **3.2 第 2 层：照片亲人模式（Photo Persona）**

* **触发条件**（满足其一）：  
  * 老人**注视某张已标注照片 \> 5 秒**（眼动追踪判定，复用注视热力能力）；  
  * 老人**开口说出照片人物的名字/称呼**（如“阿珍”“这是我老婆”，ASR \+ 记忆库人名匹配）。  
* **变身流程**：常驻角色说过渡语（“你看看这张照片……”）-\> 屏幕切换为该照片全屏 \-\> LLM 切换 Prompt 为该人物身份（“我就是阿珍呀”）-\> 以老伴/故人口吻对话。  
* **退出条件**：老人说“换个人聊聊”或静默 90 秒 \-\> 回常驻角色与待机轮播。  
* **前提**：家属端上传照片时**可选填**人物标注（名字 \+ 关系）。未标注照片不支持变身，仅参与普通轮播（保持家属端“随手传”低门槛）。

### **3.3 亲人声音匹配（声音克隆）**

* **数据来源**：家属端上传语音样本时可标注归属人（“这是阿珍的声音”），语音样本与照片人物通过**同一标注名**关联，形成 persona.voice\_sample。  
* **匹配逻辑**：照片亲人模式触发时，查该 persona 的 voice\_sample：  
  * **命中** \-\> 后端用零样本克隆（OpenVoice v2 / CosyVoice）以该音色合成 TTS——“阿珍用自己的声音”说话；  
  * **未命中** \-\> 回退默认 TTS 音色（当前语言对应音色），角色身份仍由 Prompt 承载。  
* **约束**：零样本克隆走后端预合成（上传样本时后台生成克隆音色配置并缓存），患者端只播音频，不承担克隆算力；克隆失败静默回退默认音色，绝不阻断对话。  
* **知情同意（硬性）**：家属端上传他人声音时必须勾选“我已获得本人或其监护人的同意”（见第 8、11 章）。

### **3.4 数字人形象三档渐进**

| 档位 | 形态 | 状态 | 说明 |
| :---- | :---- | :---- | :---- |
| **L1（P0 基线）** | 插画形象 \+ 呼吸微动 \+ 说话声波动画 | 必须交付 | 稳定、零依赖，保证 Demo 不翻车 |
| **L2（增强档）** | 照片亲人模式时，照片经 LivePortrait **预生成**“待机微动视频”（眨眼、轻微点头） | 时间富余则交付 | 上传照片时后台预生成视频缓存，规避实时生成延迟；效果已非常惊艳 |
| **L3（愿景）** | 音频驱动实时口型数字人（SadTalker / EchoMimic 类） | 不承诺，仅路演叙事 | 写入第 13 章落地展望 |

## **5\. 功能模块详细需求**

### **F-P01 云端配置冷启动与设备绑定（COLD\_START）**

**交互流程**（患者端零操作）：

1. 首次启动展示大字“请家人扫码设置”+ 屏幕二维码（含 6 位设备码），并循环语音提示。  
2. 家属端扫码绑定 \-\> 家属端填写配置（见第 9 章契约）-\> 上传云端。  
3. 后端按配置（地区 \* 年代 \* 语言）**动态生成资产包**（详见下）-\> 患者端拉取配置 \+ 资产包 \-\> 直接进入 STANDBY。

**动态资产包生成（绑定时刻，一次生成终身缓存）**：

* 后端 LLM 收到组合（如“浙江-1970年代-普通话”），按固定 Prompt 模板联网搜索该组合的时代公共记忆（当地地标、当年流行歌曲、标志性事件、生活场景），输出结构化资产包 JSON（照片关键词、歌单、对话话题库、Prompt 记忆锚点）；照片/歌曲从搜索结果或公版资源源获取。  
* 生成约 10-30 秒，家属端显示“正在为老人准备专属回忆…”。  
* **三层兜底**：  
  1. 搜索成功 \-\> 动态资产包缓存至云端；  
  2. 失败/超时（30s）-\> 回退按年代划分的预置通用包（3 个，不分地区），标记“待补生成”，网络恢复后重试；  
  3. 黑客松现场保险：提前为 Demo 组合（广东-80s）预生成一份本地缓存，现场演示不赌网络。

**验收标准**：

* Given 首次启动，When 页面加载完成，Then 3 秒内出现二维码页面，无任何登录框/输入框；  
* Given 家属端完成配置并生成资产包，When 患者端轮询到就绪状态，Then 自动进入 STANDBY，轮播照片全部匹配“地区 \* 年代”；  
* Given 刷新页面，When 已绑定设备，Then 跳过绑定页直接进入 STANDBY（配置与资产缓存于本地 localStorage \+ 云端）。

### **F-P02 待机老照片轮播（STANDBY）**

* 全屏老照片轮播，**10s/张**，交叉淡入淡出过渡 \>= 800ms（避免生硬切换惊吓老人）。  
* 屏幕底部仅一个常驻大按钮（麦克风图标）（默认一直监听，点击麦克风关闭监听）。  
* 眼动追踪持续运行，记录每张照片注视热力；注视 \> 5s 且照片已标注人物 \-\> 触发照片亲人模式。

**验收标准**：

* Given 老人未触屏，When 轮播进行，Then 每 10s 换张，过渡动画 \>= 800ms；  
* Given 某照片注视时长 \> 5s，When 上报数据，Then 该照片 ID 记入当日高共鸣列表；  
* Given 已标注照片被注视 \> 5s，When 触发判定，Then 进入 CHAT 且上线照片里的数字人。

### **F-P03 验证疗法双语对话（CHAT，含照片亲人模式与声音克隆）**

**交互循环**：数字人开口（TTS 0.85x，声波动画 / L2 档为微动视频）-\> 大字幕同步 \-\> 麦克风收音 \-\> ASR 识别 \-\> LLM 生成顺应式回复（\<= 40 字）-\> TTS 播报。

**核心规则**（验证疗法 Prompt 规范）：

* 时空错位输入（“我要去厂里上班”）-\> **严禁纠错**（禁止“退休/现在不是/你记错了”），顺应语境安抚（“今天厂里排休呢”）。  
* 家属端注入的记忆自然穿插引用。  
* 语言模式：粤语 \-\> TTS 粤语音色 \+ 粤语口语文案（“饮啖茶先啦”）；普通话 / 英语同理。

**照片亲人模式**（见第 3.2 节）：人名/称呼匹配触发或注视触发 \-\> Prompt 切换为该人物身份；**该 persona 存在语音样本时，TTS 使用其克隆音色**（见 3.3）。

**声学采集**：每轮对话记录犹豫潜伏期（AI 提问结束 \-\> 老人首次发声的 ms）、语速 WPM、停顿比率，随 session 上报。

**验收标准**：

* Given 老人说“我要去厂里上班了”，When LLM 返回，Then 回复不含纠错词且给出顺应式理由；  
* Given 家属端注入“海珠桥修自行车”记忆 1 分钟内，When 老人开启对话，Then 数字人 3 轮内主动提及该记忆；  
* Given 选择粤语模式，When 数字人播报，Then TTS 为粤语音色且字幕为粤语口语；  
* Given 老人注视已标注“阿珍/老伴”照片 \> 5s，When 进入 CHAT，Then 数字人以阿珍身份应答；  
* Given 该“阿珍”persona 存在已克隆音色，When 阿珍角色播报，Then TTS 使用克隆音色；Given 音色克隆失败，Then 静默回退默认音色且对话不中断；  
* Given 老人静默 90 秒，When 无语音输入，Then 自动返回 STANDBY。

### **F-P04 日落综合征舒缓模式（SOOTHING）**

**触发条件**（须全部满足）：时间 17:00-19:30；处于 CHAT/STANDBY；检测到负面信号（相同意图连续发问 \>= 3 次或音量骤升持续 10s）。

**执行动作**：

1. 屏幕色温切暖黄（CSS filter 渐变 3s）；  
2. 中断当前问答，数字人说过渡语（“天快黑了，我陪你听首歌”）；  
3. 播放高共鸣老歌（优先取注视热力最高照片对应年代歌单）；  
4. 歌曲间隙数字人简短陪伴语，**不发起任何提问**。

**验收标准**：

* Given 17:30 且老人反复问“我儿子怎么还不回来”3 次，When 第 3 次识别完成，Then 30s 内进入 SOOTHING，不再追问；  
* Given 进入 SOOTHING，When 界面渲染，Then 色温为暖黄且数字人零提问；  
* Given 20 分钟无负面信号或时间超过 19:30，When 检查，Then 自动回 STANDBY。

### **F-P05 双端真实上传 Demo 闭环**

**定位**：面向评委与开发自测的**全流程真演示**——全程无预置旁路数据，所有患者端内容由家属端真实上传产生。

**Demo 脚本**（约 3 分钟）：

1. 患者端展示绑定页二维码 \-\> 评委看着我们用家属端扫码，配置“广东-80年代-粤语”；  
2. 家属端上传 1 张照片并标注“阿珍/老伴” \-\> 患者端轮播中出现该照片；  
3. 家属端上传一段语音样本并标注“阿珍的声音” \-\> 后台零样本克隆音色就绪；  
4. 家属端发一条记忆留言（“我爸年轻时在海珠桥修自行车”）-\> 患者端数字人对话中自然引用；  
5. 老人（演示者扮演）注视“阿珍”照片 5 秒 \-\> 照片亲人模式变身，**阿珍用克隆的声音**与老人对话。

**开发自测旁路（不进路演）**：?demo=1 内置编造假数据集（假照片、假记忆节点、假语音文本、假特征流），用于无家属端联调环境下的患者端独立自测；摄像头/麦克风不可用时自动降级为假特征流驱动，保证状态机全流程可走通。

**验收标准**：

* Given 全新设备 \+ 全新家属账号，When 按 Demo 脚本执行，Then 每步在 1 分钟内于患者端可见生效（照片出现/记忆被引用/克隆音色播报）；  
* Given ?demo=1 且拒绝摄像头/麦克风权限，When 走完整流程，Then 所有状态转移正常、无白屏/卡死；  
* Given Demo 模式对话，When 输入假语音文本“我要去厂里上班”，Then 返回顺应式安抚回复。

## **6\. 埋点指标**

> 定位声明：以下指标为**认知活力与情绪状态的日常参考**，供家属端简报与照护沟通使用，**不构成任何医学诊断或筛查结论**。

| 指标 | 采集时机 | 用途 |
| :---- | :---- | :---- |
| session 时长、各状态停留时长 | 全局 | 认知活力参考因子（供家属端简报） |
| 犹豫潜伏期 / 语速 WPM / 停顿比率 | 每轮对话 | 声学参考指标 |
| 注视热力（照片级注视时长） | STANDBY / CHAT | 高共鸣话题（供家属端话题推荐） |
| 时空错位事件计数 \+ 类型标签 | CHAT | 家属端重点提示 |
| 照片亲人模式触发次数、涉及人物、是否使用克隆音色 | CHAT | 亲情联结度（供简报） |
| 日落触发次数 / 舒缓停留时长 | SOOTHING | 情绪安抚依从性 |

上报数据结构沿用 Biomarker Payload 规范，扩展字段：mode（chat/soothing）、persona（resident/photo:{memory\_id}）、voice（default/cloned）。

## **7\. 账户与鉴权**

### **7.1 患者：无账号，只认设备**

* 患者端**无任何登录概念**。首次启动生成/展示 6 位设备码（随二维码呈现），家属端扫码完成绑定。  
* 绑定成功后服务端下发**设备 token**（一次性下发，持久有效直至解绑），患者端后续所有接口凭该 token 访问。  
* 患者 ID 为服务端随机串（如 p\_88329），不含姓名/手机号等明文个人信息。

### **7.2 家属：微信手机号登录，多家属多患者**

* **登录方式**：微信手机号一键登录（MVP 简化版可为手机号 \+ 验证码）。  
* **绑定关系**：family\_user \--(care\_relation)--\> patient，**一个患者可绑定多名家属**，**一个家属可关联多位患者**（覆盖独子照顾双亲的常见场景）。  
* **家属角色**：  
  * **管理员**（首个绑定的家属）：可修改患者配置（年代/地区/语言/角色名）、管理其他家属成员、解绑设备；  
  * **成员**：可上传记忆留言、照片（含人物标注）、语音样本（含同意勾选），查看每日简报。  
* **操作审计**：所有家属写操作（记忆注入/照片/语音样本）带操作者 ID 与时间戳入库。

### **7.3 端与界面的区分**

* 患者端（相框全屏 Web）：仅凭设备 token 拉取数据，无任何家属可见功能；  
* 家属端（手机 H5/小程序）：凭用户登录态，首屏为“我关联的老人”列表，进入某患者后才能上传/查看该患者数据——**界面与权限天然按“家属 \-\> 患者”路径隔离**。  
* 越权防护：设备 token 仅能读取所属患者的资产与上报数据；家属 token 仅能操作其 care\_relation 关联的患者。

## **8\. 非功能需求**

### **8.1 适老化**

* 核心文本字号 \>= 32pt，色彩对比度 WCAG AAA（\>= 7:1）。  
* TTS 语速 0.85x，音调增强中低频共鸣。  
* 全流程老人操作 \<= 2 次点击，零文字输入。

### **8.2 隐私与加密**

* 全链路 HTTPS；接口鉴权见第 7 章。  
* 摄像头/麦克风原始流仅本地内存处理，仅上传脱敏特征数字。  
* 页面常驻小图标提示“摄像头工作中”，点击可关闭采集（硬件防窥滑盖的产品化替代，MVP 用软开关）。  
* 声音样本与照片存储于云端患者空间，仅患者端与授权家属可见；家属删除即级联删除（含克隆音色缓存）。

### **8.3 降级策略**

* LLM 不可达 \-\> 回退本地预置话术库（\>= 20 条，按语言分组），保证 Demo 不冷场。  
* 资产包生成失败 \-\> 三层兜底（见 F-P01）。  
* 声音克隆失败 \-\> 静默回退默认音色（见 3.3）。  
* ASR 失败/超时 \-\> 数字人温和重复上一句，不报错、不显示任何错误提示给老人。

## **10\. 临床依据（专业融合）**

本产品每个核心功能均对应一种**非药物干预的循证手段**，而非凭空功能堆砌：

| 功能 | 循证依据 | 说明 |
| :---- | :---- | :---- |
| 验证疗法对话引擎 | Validation Therapy（Naomi Feil，1963 年起创立） | 认可患者主观现实、严禁纠错，是失智照护界公认的沟通方法，可显著降低激惹与灾难性反应 |
| 怀旧话题/时代资产包 | Reminiscence Therapy（怀旧疗法） | 大量 RCT 证实回忆疗法可改善轻中度 AD 患者情绪与认知表现，是 NICE 指南提及的非药物干预 |
| 日落舒缓模式 | Sundowning 综合征应对策略 | 黄昏时段降低刺激、转移注意至熟悉愉悦刺激是临床照护常规手段 |
| 眼动/声学指标 | 认知衰退相关生物标志物研究 | 扫视潜伏期、言语停顿等与认知状态相关性有文献支持；本产品仅作日常参考，**不用于诊断** |

## **11\. 免责与伦理设计**

### **11.1 免责声明（患者端首次绑定后于家属端展示，并存档）**

* 本系统是**陪伴与照护支持工具，不是医疗器械**；不进行诊断、筛查判定或治疗建议；所有指标仅供日常参考，异常情况请咨询专业医师。

### **11.2 AI 身份披露策略（伦理张力的正面处理）**

* **对患者**：AI 在对话中以“老街坊/亲人”身份出现，不主动自我披露——这是验证疗法的临床要求（“机器人陪聊”标签会立即摧毁信任）。此设计决策在 PRD 与路演中**公开说明**，不隐瞒。  
* **对家属**：家属端在绑定流程中明确告知“数字人由 AI 驱动、对话内容经 LLM 生成”，并提供完整对话记录可查——知情权完整保留在监护侧。  
* **边界**：数字人被老人直接追问“你是不是机器人”时，不得撒谎（“我是陪你聊天的伙伴”，转移话题），不得断言自己是人类。

### **11.3 声音与影像克隆知情同意**

* 家属端上传他人语音样本/照片用于克隆时，必须勾选“我已获得本人或其监护人的同意”方可提交，同意记录入库；  
* 克隆音色仅用于该患者本人交互，不跨患者复用；  
* 家属删除照片/语音样本时，级联删除克隆音色与微动视频缓存；  
* 对患者播放克隆语音时，该 persona 对话界面角落常驻小字样提示（家属端演示与录屏中可见，字号对老人不构成干扰）。

### **11.4 数据最小化**

* 原始音视频永不上传（本地特征提取）；  
* 患者 ID 去标识化；上传 LLM 的上下文仅含脱敏结构化数据，接口开启零数据保留（Zero-Data Retention）策略。

## **13\. 落地展望（孵化与公益路径）**

* **社区养老机构**：相框设备 \+ 家属端订阅，机构护理员以“管理员家属”角色批量管理，缓解护理员沟通压力——B2B2C 路径；

* **硬件化路线**：浏览器架构天然可移植至安卓相框/树莓派一体机（Web 容器 \+ 物理防窥滑盖 \+ 麦克风断电开关）；  
* **L3 数字人愿景**：音频驱动实时口型（SadTalker/EchoMimic 类）+ 更长录音微调克隆，让“亲人复活对话”完全体落地；  
* **记忆资产的家庭传承价值**：老人与数字人的对话记录、口述内容经家属授权沉淀为“家庭记忆库”，反哺每日老故事连环画——产品情感价值随时间复利增长。

### **15.3 四大状态前端动效视觉细则**

1. **COLD\_START（首次配置）**：  
   * 界面意象为“桌上一封未启封的书信”；  
   * 居中呈现墨水楷体温和提示，大号二维码带柔和扩散光晕动效；下方以 36pt 等宽清晰字体排列 6 位设备码；  
   * WebSocket 收到家属端绑定成功事件后，二维码呈墨滴晕开动画（淡出时长 \>= 1.2s），首张年代照片缓慢显影。  
2. **STANDBY（待机老照片轮播）**：  
   * **Ken Burns 电影感视效**：照片以极慢速度（10s 内从 scale(1.0) 缓动至 scale(1.05)，平移 \<= 2%），叠加微妙的老胶片微暗角（Vignette Filter）；  
   * 切换照片时淡入淡出时长 \>= 800ms；  
   * 底部常驻微光呼吸的麦克风浮动按钮（直径 \>= 72px）；照片左下角短暂浮现年代地点标签（3s 后自动隐去）。  
3. **CHAT（验证疗法陪聊 & 照片亲人变身）**：  
   * **常驻老街坊形象**：手绘和善水彩半身插画，CSS 实现轻微胸腔起伏呼吸动效（周期 3s）；发声时身旁扩散柔和同心涟漪声波环；  
   * **适老大字幕**：字号 \>= 34pt，胶囊高对比深色背景，配合逐字平滑高亮；  
   * **照片亲人变身高光转场**：注视超 5s 判定生效后，常驻角色温和念出过渡语，老照片居中瞬间平滑放大至全屏，四周边缘泛起暖金景深光斑，克隆声音介入。  
4. **SOOTHING（日落综合征舒缓）**：  
   * 触发时全屏经 CSS Filter 3s 渐变到 2700K 暖黄烛光色温（sepia(0.35) saturate(1.2)）；  
   * 数字人转为静默抱膝/托腮倾听姿态；  
   * 屏幕中央呈现一架慢速匀速旋转的复古黑胶唱片（圆心为高共鸣老照片），外缘泛起声波水纹律动，底部展示老歌大字名。

### **15.4 前端防呆与鲁棒性交互设计**

1. **防误触与零认知负担（Zero-Cognition Load）**：  
   * 禁用右键菜单、双指捏合缩放（touch-action: manipulation; user-select: none;）；  
   * 彻底摒弃一切输入框、下拉选单与右上角微小关闭叉号（×）；  
   * 所有触控目标区域最小尺寸 \>= 64px。  
2. **隐藏式运维暗门**：  
   * 演示者快速连续点击相框右上角 3 次，可唤起轻量级运维菜单（提供：重置绑定设备码、手动触发日落模式、切换三语演示流）。  
3. **权限降级温和处理**：  
   * 若麦克风/摄像头被浏览器弹窗拦截，界面不显示红色“403 / 权限错误”，而是由强叔以漫画对话框形式温和提示：*“强叔耳朵有点背，请在浏览器上方允许使用麦克风哦”*。
