## 1. 产品概述

### 1.1 产品定位

RetinaEcho 是面向轻中度阿尔茨海默病患者家庭的非临床陪伴与照护支持产品，由两个相互协作的终端组成：

- **患者端**：运行在 iPad 或 PC 浏览器中的全屏数字记忆相框，以老照片、熟悉声音和“老街坊/亲人”角色提供低操作负担的怀旧陪伴、验证疗法对话和日落舒缓。
- **家属端**：运行在手机 Web/H5 中的配置与监护入口，负责账户登录、患者绑定、家庭成员管理、全部业务授权与同意、记忆素材录入以及每日照护简报查看。

系统采集的眼动与声学特征只用于形成个人日常状态参考，不进行医学诊断、筛查判定或治疗建议，不替代医生与专业照护人员。

### 1.2 核心问题

1. 患者不适应复杂数字产品，不能承担登录、输入、配置和授权流程。
2. 家属希望了解患者日常状态，却缺少低门槛的沟通方法和持续记录手段。
3. 通用 AI 缺乏患者个人记忆，上线即为空壳，难以建立信任和情感连接。
4. 双端若缺少统一的患者身份、权限和数据契约，容易出现重复建档、越权访问和素材错投。

### 1.3 产品原则

- **患者端零配置**：患者无账号、零文字输入，日常操作不超过两次点击。
- **家属端统一治理**：所有业务权限、授权说明、同意/拒绝、成员管理和数据管理均在家属端呈现并留痕。
- **熟悉感优先**：以年代公共记忆完成冷启动，再用家庭私有记忆持续个性化。
- **顺应而不纠错**：患者出现时空错位表达时，采用验证疗法式回应，避免正面纠正。
- **隐私最小化**：患者端原始摄像头和麦克风流默认只在本地处理，云端仅接收实现功能所需的数据。
- **去医学化**：面向家属只展示易理解的日常参考和沟通建议，不输出诊断性结论。

### 2.3 MVP 运行载体

- 患者端：iPad/PC 的 Safari 或 Chrome 全屏 Web，需前置摄像头、麦克风和扬声器。
- 家属端：手机 Web/H5，Mobile First，适配 iOS Safari、微信内置浏览器和 Android Chrome。
- 演示形态：笔记本电脑模拟患者相框，手机展示家属端。

## 3. MVP 范围与成功标准

### 3.1 P0 范围

1. 家属手机号验证码登录与首次注册。
2. 患者设备扫码绑定、同一患者的多家属邀请加入、角色权限管理。
3. 家属端完成统一授权、同意和配置；患者端自动冷启动。
4. 患者端老照片轮播、验证疗法对话、照片亲人模式与声音克隆降级。
5. 家属端通过文字、语音或照片增量录入记忆，结构化后同步患者端。
6. 患者端采集本地眼动/声学参考特征，家属端查看每日简报。
7. 日落时段的舒缓模式。
8. 双端真实上传演示闭环和患者端独立 Demo 降级模式。

### 3.2 成功标准

1. 新设备展示二维码后，家属可在 3 分钟内完成登录、绑定、同意和基础配置，患者端自动进入待机页。
2. 家属上传“我爸年轻时在海珠桥修自行车”后 1 分钟内，患者端对话能自然引用该记忆。
3. 患者表达“我要去厂里上班”时，系统给出顺应式安抚，不出现“你退休了”“你记错了”等纠错措辞。
4. 管理员邀请第二位家属后，两人进入的是同一个患者空间，看到相同患者 ID 下的配置、素材与简报。
5. 未获授权的家属不能访问或修改任何患者数据；成员不能执行管理员专属操作。
6. 全新家属账号和全新患者设备可完成真实上传闭环，不依赖路演预置旁路数据。

## 4. 统一业务流程与数据流

### 4.1 首次使用主流程

```text
患者端首次打开
  → 生成一次性绑定会话，展示二维码与 6 位设备码
  → 家属端登录/注册并扫码
  → 服务端创建 patient_id、管理员 care_relation 和设备记录
  → 家属端完成知情同意及年代/地区/语言配置
  → 后端生成或加载公共时代资产包
  → 向患者设备签发 device_token
  → 患者端自动进入 STANDBY
```

### 4.2 增量记忆闭环

```text
家属输入文字/语音/照片
  → ASR/对象存储预处理
  → LLM 结构化抽取并计算 extraction_confidence
  → 家属端展示记忆卡片
  → 高置信结果可 3 秒默认确认；低置信结果必须由家属确认或修改
  → 写入该 patient_id 的记忆库
  → 患者端拉取更新并用于轮播、角色匹配和对话检索
```

### 4.3 每日简报闭环

```text
患者端本地提取眼动/声学特征
  → 上传脱敏数值与交互事件
  → 后端按患者个人基线聚合
  → 生成日常状态、共鸣话题和验证疗法沟通建议
  → 授权家属在家属端查看
```

## 5. 账户、患者身份与鉴权

### 5.1 家属端登录与注册

- MVP 采用**手机号 + 验证码**登录；手机号首次验证成功即完成注册，无需单独设置密码。
- 验证码 5 分钟内有效，同一手机号 60 秒内不可重复发送；连续失败 5 次后锁定 15 分钟。
- 登录成功后签发短期 access token 与可轮换 refresh token。
- 家属退出登录或账户被移除后，当前设备上的令牌立即失效。
- 微信手机号一键登录作为后续增强项；无论入口如何，均归一到唯一 `family_user_id`。

### 5.2 如何确定不同家属绑定的是同一个患者

**唯一判断依据是服务端生成的 `patient_id`，不是姓名、手机号、设备名称或家属自行填写的信息。**

1. 患者端首次生成未绑定的 `binding_session_id`、二维码和 6 位设备码。
2. 第一位完成扫码与配置的家属触发创建唯一 `patient_id`，并成为该患者的家属管理员。
3. 设备记录写入 `patient_id`，服务端为设备签发只属于该患者的 `device_token`。
4. 其他家属必须通过管理员在家属端生成的邀请二维码/邀请码加入已有 `patient_id`，不得再次扫码创建一个“同名患者”。
5. 邀请码单次使用、30 分钟有效，并绑定目标 `patient_id` 和预设角色；使用成功或被管理员撤销后立即失效。
6. 加入前向受邀家属展示患者昵称、关系称谓和管理员脱敏手机号，受邀家属二次确认后建立 `care_relation`。
7. 患者昵称仅用于界面展示，不参与身份判定；MVP 不尝试通过姓名或照片自动合并患者，避免误合并。

数据关系为：

```text
family_user ──< care_relation >── patient ──< patient_device
```

- 一个患者可关联多名家属。
- 一个家属可关联多位患者。
- MVP 默认一个患者绑定一台在用相框设备；换机必须由管理员发起，旧设备令牌随换机失效。

### 5.3 家属角色与权限矩阵

| 操作 | 管理员 | 成员 |
| :--- | :---: | :---: |
| 查看患者状态与每日简报 | ✓ | ✓ |
| 添加文字/语音记忆 | ✓ | ✓ |
| 上传照片并标注人物 | ✓ | ✓ |
| 上传声音样本 | ✓ | 需管理员已开启该能力 |
| 确认或修改低置信记忆 | ✓ | 仅本人提交内容 |
| 修改年代、地区、语言、常驻角色名 | ✓ | — |
| 开关眼动/声学采集 | ✓ | — |
| 接受/撤回产品级知情同意 | ✓ | — |
| 邀请、移除成员及调整角色 | ✓ | — |
| 解绑/更换患者设备 | ✓ | — |
| 导出或删除患者全部数据 | ✓ | — |

规则：

- 首位绑定者默认成为管理员；MVP 每个患者仅设一名管理员。
- 管理员移交必须由当前管理员在家属端确认，移交后原管理员降为成员。
- 管理员移除成员后，该成员的患者访问权限和令牌授权立即失效，但其历史操作保留审计记录。
- 所有服务端接口均以 `family_user_id + patient_id + care_relation.role` 校验，不信任前端按钮是否可见。

### 5.4 患者端设备鉴权

- 患者无账号、无登录页。
- 绑定成功后患者端获得不可读出、不可跨患者使用的 `device_token`。
- `device_token` 只能读取所属患者的配置与资产、上报所属患者的交互特征，不能调用家属管理接口。
- 管理员解绑、换机或报告设备丢失后，服务端撤销旧 `device_token`。
- 6 位设备码只用于短时绑定，不得作为长期访问凭证。

## 6. 权限、同意与隐私控制

### 6.1 统一原则

关于患者端和家属端的全部**业务权限、知情说明、同意与拒绝**，均在家属端呈现并由家属管理员确认。患者端不承担阅读条款、做业务选择或管理家庭成员的责任。

### 6.2 家属端同意中心

首次绑定必须逐项展示并记录以下内容：

| 同意项 | 默认值 | 是否必需 | 撤回后行为 |
| :--- | :---: | :---: | :--- |
| AI 陪伴与生成内容说明 | 未同意 | 必需 | 停止 AI 对话，保留基础相框功能 |
| 非医疗器械及非诊断声明 | 未确认 | 必需 | 不得完成绑定 |
| 眼动特征采集 | 关闭 | 可选 | 患者端停止摄像头特征处理 |
| 声学特征采集 | 关闭 | 可选 | 患者端停止声学指标提取；语音对话另行提示所需麦克风 |
| 对话记录用于家属简报 | 关闭 | 可选 | 不保存对话内容，仅保留必要运行日志 |
| 私有记忆云端存储 | 未同意 | 必需 | 停止新增记忆；删除须另行二次确认 |
| 声音克隆能力 | 关闭 | 可选 | 停止使用克隆音色并删除克隆配置 |
| 照片微动/影像生成 | 关闭 | 可选 | 停止生成与播放微动视频 |

- 同意记录包含 `consent_type`、条款版本、同意状态、操作者、患者 ID、时间和撤回时间。
- 可选能力拒绝后，产品必须提供可用的降级体验，不阻断基础相框和默认音色陪伴。
- 管理员可在家属端“隐私与授权”页查看、修改和撤回同意。
- 高风险动作（声音克隆、全量删除、解绑设备）必须二次确认，不允许 3 秒默认确认。

### 6.3 他人声音与影像授权

- 每次上传他人声音或用于人物微动的照片时，提交者必须勾选“我已获得本人或其监护人的授权”。
- 该素材级授权与产品级能力开关必须同时有效，素材才可进入处理流程。
- 声音与影像只能用于指定 `patient_id`，不得跨患者复用。
- 删除原素材时级联删除克隆音色、微动视频和相关缓存。

### 6.4 浏览器系统权限的技术例外

摄像头和麦克风的浏览器系统弹窗无法由另一台设备远程代为授权。为保持业务责任仍在家属侧，按以下方式处理：

1. 管理员先在家属端同意对应业务能力并打开采集开关。
2. 患者端首次启用时进入一次性“照护者设置”页，由照护者在患者设备上点击浏览器的允许按钮。
3. 患者端不展示条款选择，只显示“请家人完成设备设置”的大字和语音提示。
4. 浏览器权限被拒绝时，家属端显示处理指引；患者端自动降级，不向患者展示技术错误。
5. 家属端撤回同意后，即使浏览器系统仍保留授权，应用也必须停止调用对应硬件。

## 7. 患者端产品需求

### 7.1 全局状态机

| 状态 | 主界面 | 进入条件 | 退出条件 |
| :--- | :--- | :--- | :--- |
| COLD_START | “请家人扫码设置”+ 二维码 + 设备码 | 首次启动或已解绑 | 配置与必要同意完成后自动进入 STANDBY |
| CAREGIVER_SETUP | “请家人完成设备设置” | 家属端开启需系统权限的能力 | 照护者完成或跳过技术授权 |
| STANDBY | 老照片全屏轮播 | 冷启动完成或对话结束 | 触屏、语音或已标注照片触发 CHAT |
| CHAT | 数字人/照片人物 + 大字幕 | 用户发起对话或人物模式触发 | 静默 90 秒返回；满足条件进入 SOOTHING |
| SOOTHING | 暖色温 + 老歌 + 陪伴姿态 | 日落时段检测到负面信号 | 平稳 20 分钟或超过 19:30 返回 STANDBY |

### 7.2 F-P01 冷启动与配置拉取（P0）

1. 页面加载后 3 秒内展示二维码、6 位设备码和循环语音提示，不展示登录框或文字输入框。
2. 家属端完成绑定、必要同意和配置后，患者端通过绑定会话轮询获取设备令牌与配置。
3. 后端按地区、年代和语言生成公共资产包；30 秒超时则回退年代通用包，网络恢复后后台补生成。
4. Demo 组合“广东/1980s/粤语”预生成本地缓存，保证现场稳定。
5. 已绑定设备刷新页面时跳过绑定页；设备令牌失效时安全返回 COLD_START。

### 7.3 F-P02 待机老照片轮播（P0）

- 每 10 秒切换一张照片，淡入淡出不少于 800ms。
- 界面仅保留大号“聊聊”入口和麦克风状态，不提供设置、权限或同意入口。
- 获得眼动业务同意和浏览器权限时，本地统计照片级注视时长；否则不初始化摄像头能力。
- 已标注人物的照片被连续注视超过 5 秒时，可进入照片亲人模式；未标注照片只参与轮播。
- 任一照片累计注视达到 30 秒、围绕话题对话达到 3 轮或主动提及达到 2 次时，标记为高共鸣候选。

### 7.4 F-P03 验证疗法对话（P0）

- 支持普通话、粤语和英语 ASR/TTS；默认 TTS 语速为 0.85x。
- 每轮回复不超过 40 个汉字或等量英文，优先短句、熟悉词汇和温和语气。
- 对时空错位表达严禁正面纠错，采用顺应、安抚和转移注意力的方式回应。
- 家属确认后的个人记忆应在同步后 1 分钟内可被对话检索使用。
- ASR 失败时温和重复或提示“慢慢说，我听着”，不展示错误码。
- LLM 不可达时回退按语言分组的本地话术库。

### 7.5 F-P04 照片亲人模式与声音匹配（P0）

触发条件满足其一：

- 注视已标注人物照片超过 5 秒；
- 语音中匹配到已标注人物的名字或称谓。

处理规则：

1. 常驻角色播放过渡语后切换到人物照片。
2. LLM 使用该人物的关系和记忆上下文，但不得编造未录入的共同经历。
3. 存在已授权且处理成功的声音样本时使用克隆音色；否则无提示地回退默认音色。
4. 人物主数据使用 `persona_id` 关联照片和声音，不使用易重名的人物姓名做数据库关联键。
5. 患者说“换个人聊聊”或静默 90 秒后退出人物模式。

### 7.6 F-P05 日落舒缓模式（P0）

仅当时间为 17:00–19:30，且检测到以下任一信号时触发：

- 相同意图连续出现不少于 3 次；
- 音量显著升高并持续 10 秒。

进入后屏幕在 3 秒内渐变为暖色，播放熟悉老歌，数字人只给出简短陪伴语，不主动提问。20 分钟未再出现负面信号或时间超过 19:30 时返回待机。

## 8. 家属端产品需求

### 8.1 F-F00 登录、患者列表与首次绑定（P0）

- 未登录用户先完成手机号验证码登录/注册，再使用扫码或手输 6 位设备码绑定。
- 登录后首屏为“我照护的人”，每张卡片展示患者昵称、关系、设备在线状态和最近同步时间。
- 首次绑定依次完成：患者昵称与关系 → 出生年代 → 国家/地区 → 语言 → 同意中心 → 生成资产包。
- 常驻角色名为可选项，默认“强叔”。
- 资产生成期间显示进度；失败时明确告知已使用通用包，不阻断建档。

### 8.2 F-F01 家庭成员管理（P0）

- 管理员可生成邀请二维码/邀请码并预设受邀者为“成员”。
- 受邀者必须登录自己的家属账号后加入，不共享管理员账号。
- 加入前需核对患者昵称、关系和管理员脱敏手机号，并明确确认“加入该患者的家庭空间”。
- 管理员可查看成员列表、加入时间和最近操作，可移除成员或移交管理员。
- 成员访问多个患者时，每次操作都必须先进入明确的患者空间，页面顶部常驻显示当前患者昵称。

### 8.3 F-F02 微信式增量记忆建档（P0）

- 支持文字短句、5–10 秒语音和单张照片；照片可与文字或语音联合提交。
- 语音经 ASR 转写，照片上传对象存储并生成缩略图，再由 LLM 做结构化抽取。
- 记忆卡片展示原文、照片、年代、地点、事件、喜好和人物标注，提供编辑、确认、删除入口。
- 家属可为照片中的人物创建或选择 `persona_id`，填写显示名称和关系。
- 记忆未确认前状态为 `pending_confirmation`，不得进入患者端记忆检索。

### 8.4 F-F03 每日状态简报（P0）

每日简报支持按日期翻阅，包含：

1. **日常活力状态**：展示“精神活跃/状态平稳/建议多关注”等去医学化等级及相对个人基线的趋势。
2. **高共鸣话题 Top 3**：展示话题、照片、注视时长、互动轮次和主动提及次数。
3. **验证疗法沟通建议**：给出 1–2 条具体聊天切入点和避免纠错的示例。
4. **舒缓记录**：展示日落舒缓触发次数和持续时间，不使用“发病次数”等医疗化措辞。

简报页固定展示：“仅供日常照护参考，不构成医学诊断或筛查结论。如持续异常，请咨询专业医师。”

### 8.5 F-F04 设备、隐私与授权设置（P0）

- 展示患者设备的在线/交互中/离线状态及最近同步时间。
- 管理员可查看并控制眼动、声学、对话记录、声音克隆和照片微动开关。
- 浏览器系统权限未完成时展示患者设备侧的操作指引。
- 支持解绑、换机、撤回同意、按素材删除和删除患者全部数据。
- 删除患者全部数据前需输入患者昵称二次确认，并说明删除范围与不可恢复性。

## 9. 记忆抽取与置信度规则

### 9.1 置信度的用途

`extraction_confidence` 表示模型对“本次记忆实体抽取是否可靠”的内部估计，范围为 0–1。它只用于决定是否需要家属复核：

- 它**不是**患者认知、健康或疾病风险的置信度。
- 它不在患者端展示，不参与每日活力状态计算。
- 家属端默认不展示小数，只转换为“已识别，可确认”或“需要你确认”。调试模式可查看原始值。
- 置信度不能替代家属对声音、影像和隐私授权的明确同意。

### 9.2 分流规则

| 条件 | 家属端表现 | 是否自动同步 |
| :--- | :--- | :---: |
| 无任何有效实体 | 提示换一种说法；保留输入草稿 | 否 |
| `confidence < 0.6` | 标记“需要你确认”，高亮不确定字段 | 否，必须确认或修改 |
| `confidence >= 0.6` | 展示完整卡片和 3 秒撤销倒计时 | 是，3 秒无操作后确认 |
| 家属手动编辑 | 以家属修改值为准并记录修订 | 确认后同步 |
| LLM 输出校验失败 | 自动纠正重试 1 次；仍失败则仅保存原文待确认 | 否 |

涉及人物身份时，即使总体置信度不低于 0.6，系统也不得仅凭照片自动认定真实人物。家属必须选择已有 `persona_id` 或新建人物后，照片才可触发亲人模式。

### 9.3 结构化 Schema

```json
{
  "memory_id": "mem_001",
  "patient_id": "p_88329",
  "created_by": "family_2001",
  "raw_input": "我爸年轻时在海珠桥修自行车，最喜欢喝铁观音",
  "entities": {
    "era": "1970s-1980s",
    "locations": ["海珠桥"],
    "event": "修自行车",
    "preferences": ["铁观音"],
    "photo_id": null,
    "persona_ids": []
  },
  "extraction_confidence": 0.95,
  "uncertain_fields": [],
  "confirmation_status": "confirmed",
  "confirmed_by": "family_2001"
}
```

## 10. 日常参考指标与简报规则

### 10.1 采集指标

| 指标 | 采集端 | 用途 |
| :--- | :--- | :--- |
| 状态停留时长、会话时长 | 患者端 | 描述当日互动程度 |
| 照片/话题注视时长 | 患者端本地计算 | 识别高共鸣内容 |
| 回答犹豫潜伏期 | 患者端本地计算 | 描述相对个人基线的反应变化 |
| 语速与停顿比率 | 患者端本地计算 | 描述表达连续性变化 |
| 时空错位事件标签 | 对话后端 | 生成家属沟通建议 |
| 人物模式与舒缓模式记录 | 患者端/后端 | 描述情感联结与舒缓使用情况 |

### 10.2 日常活力状态

- MVP 只比较患者自身近 7 个有效使用日的基线，不与人群常模比较。
- 使用日不足 3 天时不输出趋势，只显示“正在了解日常状态”。
- 内部可保留 0–100 分用于排序和趋势计算，家属端默认展示等级和变化描述，避免制造医学精确度错觉。
- 初版权重：注视/互动子分 40%，回答反应子分 30%，表达连续性子分 30%。权重仅为工程初值，未经临床样本校准不得对外宣称医学有效性。
- 不使用“认知衰退度”“患病风险”“建议就医随访分”等诊断导向名称。

### 10.3 高共鸣话题

满足任一条件即进入候选：累计注视不少于 30 秒、相关对话不少于 3 轮、主动提及不少于 2 次。

```text
共鸣分 = 注视时长（秒） + 对话轮次 × 10 + 主动提及次数 × 5
```

按分数倒序取 Top 3，仅用于推荐家属沟通话题，不代表医学改善。

## 11. 共享技术与接口契约

### 11.1 建议技术底座

| 能力 | 建议技术 | 约束 |
| :--- | :--- | :--- |
| 眼动/视线 | MediaPipe FaceMesh（浏览器端） | 本地处理，不上传视频 |
| 声学特征 | Web Audio API（浏览器端） | 本地计算，不上传原始连续音频 |
| 后端 | FastAPI + 可替换 LLM | 模型型号不写死在产品契约中 |
| ASR/TTS | 普通话/粤语/英语服务 | 对话需低延迟；失败可降级 |
| 声音克隆 | OpenVoice v2/CosyVoice 零样本模式候选 | 仅处理已授权素材，失败回默认音色 |
| 照片微动 | LivePortrait 预生成候选 | 非实时生成，不阻断基础体验 |

### 11.2 核心对象

- `family_user`：家属登录主体。
- `patient`：跨家属、跨设备保持稳定的患者业务主体。
- `care_relation`：家属与患者的关联及角色。
- `patient_device`：患者相框设备及令牌状态。
- `consent_record`：产品级和素材级同意记录。
- `persona`：照片人物主数据，作为照片和声音的稳定关联键。
- `memory`：家属确认后的记忆节点。
- `daily_summary`：按患者和日期聚合的家属简报。

### 11.3 关键接口能力

| 能力 | 示例接口 | 鉴权主体 |
| :--- | :--- | :--- |
| 请求验证码/登录 | `POST /api/auth/otp/request`、`POST /api/auth/otp/verify` | 匿名/家属 |
| 扫码首次绑定 | `POST /api/family/bindings` | 家属 |
| 创建/接受邀请 | `POST /api/patients/{id}/invites`、`POST /api/invites/{code}/accept` | 管理员/家属 |
| 更新同意 | `PUT /api/patients/{id}/consents/{type}` | 管理员 |
| 添加/确认记忆 | `POST /api/patients/{id}/memories`、`POST /api/memories/{id}/confirm` | 授权家属 |
| 上传人物素材 | `POST /api/patients/{id}/personas/{persona_id}/assets` | 授权家属 |
| 获取患者配置 | `GET /api/device/config` | 患者设备 |
| 上报脱敏特征 | `POST /api/device/events` | 患者设备 |
| 获取每日简报 | `GET /api/patients/{id}/summaries/{date}` | 授权家属 |

所有患者级接口必须校验路径中的患者 ID 与令牌可访问范围一致，禁止仅依赖前端传入的 `patient_id`。

## 12. 非功能需求

### 12.1 性能

- 患者端冷启动页 3 秒内可见。
- 纯文本记忆抽取目标不超过 1.5 秒，照片联合抽取目标不超过 3 秒。
- 文本记忆确认后 3 秒内完成双端同步，含照片时不超过 5 秒；现场网络不稳定时允许先显示同步中并自动重试。
- 患者端对话失败不得白屏或卡死，必须回退本地话术或待机状态。

### 12.2 易用性与无障碍

- 患者端核心字号不少于 32pt，对比度达到 WCAG AAA（不少于 7:1）。
- 家属端主干字号不少于 16pt，关键按钮提供足够点击区域。
- 患者端不显示面向开发者的错误、置信度、医学术语或复杂设置。

### 12.3 安全与隐私

- 全链路 HTTPS；敏感数据静态加密。
- 摄像头视频与连续环境音频不上传；对话所需短时语音应明确区别于声学特征采集，并按同意策略处理。
- 所有家属写操作记录操作者、患者 ID、动作、目标对象、时间和结果。
- 家属移除、解绑、撤回同意后，权限与数据处理状态应在 1 分钟内生效。
- 日志不得记录验证码、完整令牌、原始声音样本或可直接访问的私有素材 URL。

## 13. 免责与伦理设计

1. 家属端首次绑定时明确说明：本产品是陪伴与照护支持工具，不是医疗器械，不提供诊断、筛查或治疗建议。
2. 患者端角色可以采用“老街坊/熟悉人物”的交互外壳，但被直接问“你是不是机器人”时不得断言自己是人类，可回答“我是陪你聊天的伙伴”。
3. 家属端明确披露对话由 AI 生成，以及照片、声音可能被用于合成内容。
4. 不得使用低落、重复提问或活力状态做自动医疗告警；只提供温和的关注建议。
5. 任何声音或影像合成都必须满足产品级开关和素材级授权双重条件。

## 15. 双端真实上传 Demo 脚本

1. 患者端打开冷启动页，展示二维码。
2. 演示者在家属端使用新账号登录并扫码，完成“广东/1980s/粤语”配置和必要同意。
3. 患者端自动进入待机并显示时代资产。
4. 家属端创建“阿珍/老伴”人物，上传照片并完成影像授权；照片出现在患者端轮播。
5. 家属端上传“阿珍”的声音样本并完成声音授权；后端生成克隆配置。
6. 家属发送“我爸年轻时在海珠桥修自行车”，确认记忆卡片；患者端对话在 1 分钟内引用。
7. 演示者注视阿珍照片 5 秒，患者端切换人物模式；克隆成功时使用阿珍音色，失败时使用默认音色且流程不中断。
8. 管理员生成邀请码，第二个家属账号加入，展示两位家属看到同一个患者空间。

患者端 `?demo=1` 仅用于开发自测，可在无摄像头、麦克风或家属端联调环境下使用假特征流；路演真实闭环不得使用该旁路。

## 17. 范围外

- 40Hz 声光刺激或其他物理刺激干预。
- 医生端、临床诊断、筛查结论和自动医疗告警。
- 真实硬件相框量产与远场人体感应。
- 实时口型数字人及声音微调训练；MVP 仅使用预生成微动与零样本声音克隆。
- 通过姓名、照片或身份证自动合并患者档案。
- 多管理员、复杂机构权限和一个患者多台同时在线设备。
- 独立老歌播放器；老歌仅作为舒缓模式内容。

## 18. 原双端 PRD 冲突处理说明

| 原有分歧/缺口 | 统一结论 |
| :--- | :--- |
| 患者端 PRD 将家属端界面列为范围外，家属端 PRD 又依赖双端闭环 | 统一 PRD 将两个终端都纳入产品范围，并分别定义职责 |
| 家属端缺少登录、注册和多家属绑定规则 | 增加手机号验证码登录、唯一 patient_id 和管理员邀请机制 |
| 原文以人物名称精确匹配照片与声音 | 改为稳定的 persona_id，名称只用于展示 |
