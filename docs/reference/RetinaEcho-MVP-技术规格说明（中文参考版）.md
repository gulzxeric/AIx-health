**状态：** 待研发评审

**产品依据：** `PRD/数字记忆相框（双端统一）PRD.md`

**正式技术依据：** `spec/2026-09-04-retinaecho-mvp-design.md`

## 1. 目标与硬性原则

本 Spec 将统一 PRD 转换为可实施的技术设计，覆盖双端边界、数据模型、登录鉴权、患者绑定、权限与同意、接口、异步任务、异常降级、安全和测试。

实现必须遵守四条红线：

1. 患者不创建账号，也不承担业务授权或知情同意。
2. 服务端生成的 `patient_id` 是关联设备、家属、记忆、媒体和简报的唯一患者身份。
3. 所有患者级访问都在服务端鉴权，不能把“前端隐藏按钮”当成权限控制。
4. `extraction_confidence` 只决定记忆是否需要家属复核，不代表患者健康、认知或疾病风险。

## 2. 技术架构

采用两个独立 Web 前端、一个 FastAPI 模块化单体、一个后台 Worker：

```text
患者端全屏 PWA ──┐
                  ├── HTTPS / WebSocket ── FastAPI 模块化单体
家属端移动 PWA ──┘                              │
                          ┌─────────────────────┼──────────────────┐
                          ▼                     ▼                  ▼
                     PostgreSQL              Redis             对象存储
                          ▲                     │                  ▲
                          └──────── 后台任务 Worker ───────────────┘
```

### 2.1 各组件职责

| 组件 | 职责 |
| :--- | :--- |
| 患者端 Web | 设备绑定、状态机、照片轮播、对话、舒缓、本地传感器特征提取 |
| 家属端 Web | 登录、患者选择、配置、成员、授权、记忆、素材和每日简报 |
| FastAPI | 同步接口、鉴权、事务、业务规则和查询 |
| Worker | 资产包、记忆抽取、向量化、声音克隆、照片微动和每日简报 |
| PostgreSQL | 用户、患者、关系、同意、记忆和审计等权威数据 |
| Redis | 验证码、绑定会话、邀请码、限流、缓存和任务协调 |
| 对象存储 | 私有照片、声音样本及派生媒体 |

采用模块化单体而非微服务，是为了让四人团队共享一套契约和本地环境，同时保留清晰领域边界。AI 与媒体处理通过异步任务隔离，不能阻塞普通 API 请求。

## 4. 核心数据模型

### 4.1 ID 与时间约定

- 持久化主键使用 UUIDv7。
- 对外使用不透明前缀 ID：`fam_`、`pat_`、`dev_`、`per_`、`mem_`。
- 昵称、姓名、手机号和人物显示名均不得作为关联键。
- API 时间统一为 UTC RFC 3339，数据库使用 `timestamptz`。

### 4.2 核心实体

#### `family_users`

家属登录主体。手机号按 E.164 标准化后应用层加密；另存带密钥哈希用于唯一查找。状态为 `active`、`locked` 或 `deleted`。

#### `patients`

患者业务主体。包含唯一 `patient_id`、家属可见昵称、出生年代、地区、语言、常驻角色名和状态。患者昵称只负责展示，不能用于自动合并。

#### `care_relations`

家属与患者的关联，角色为 `admin` 或 `member`。约束如下：

- 同一家属与同一患者只能存在一条有效关系。
- 一个患者只能有一名有效管理员。
- 管理员移交必须在同一数据库事务内完成旧管理员降级与新管理员升级。

#### `patient_devices`

患者相框设备。保存所属患者、令牌版本、状态、最近在线时间。MVP 一个患者只允许一台有效设备；换机必须先撤销旧设备再启用新设备。

#### `consent_records`

同意记录采用追加写，不覆盖历史。记录患者、同意类型、条款版本、状态、操作者和时间；当前状态取该类型最新一条记录。

#### `personas`

照片人物主数据，包含稳定 `persona_id`、显示名和关系。照片与声音样本都通过 `persona_id` 关联，禁止按“阿珍”等名字做精确匹配。

#### `media_assets`

保存患者、人物、媒体类型、私有对象键、哈希、类型、大小、授权记录和处理状态。声音与人物照片在进入生成流程前必须有素材级授权记录。

#### `memories`

保存患者、提交者、原文、结构化实体、抽取置信度、不确定字段、确认状态、确认人和修订号。只有 `confirmed` 记忆能进入患者对话检索。

#### `interaction_events`

保存患者端脱敏交互事件，如状态停留、照片注视聚合、对话轮次和舒缓记录。接口拒绝原始视频、连续环境音频、未知事件和超大 Payload。

#### `daily_summaries`

按 `(patient_id, local_date)` 唯一，保存算法版本、数据覆盖率、内部子分、家属展示等级、Top 话题和沟通建议。

## 5. 登录与会话

### 5.1 家属验证码登录

1. 家属提交 E.164 手机号请求验证码。
2. 服务端生成随机 6 位验证码，Redis 只保存带密钥哈希，有效期 5 分钟。
3. 同一手机号 60 秒内只能请求一次；单次挑战最多失败 5 次。
4. 连续失败达到上限后锁定 15 分钟。
5. 首次验证成功创建家属账号，后续复用原账号。
6. 返回 15 分钟 Access Token 和 30 天可轮换 Refresh Token。
7. Refresh Token 只存哈希；旧 Token 被重复使用时撤销整组会话。

Access Token 不嵌入患者角色，因为角色可能随时被移除或调整。每个患者请求都必须读取当前有效的 `care_relation`。

### 5.2 患者设备令牌

设备令牌包含设备 ID、患者 ID、令牌版本和 `scope=device`。Access Token 有效期 15 分钟，Refresh Token 有效期 90 天并轮换使用。

管理员解绑、换机或报告丢失时，服务端递增设备令牌版本并撤销 Refresh Token。设备令牌只能读取所属患者配置、资产并上报事件，不能调用家属管理接口。

## 6. 首次绑定与多家属加入

### 6.1 绑定会话

患者端创建 10 分钟有效的绑定会话，得到二维码和 6 位设备码。Redis 保存设备码哈希、会话状态、到期时间和失败次数，不保存可直接读取的设备码。

### 6.2 首位家属绑定事务

家属登录并扫码后提交患者基础信息和必要同意。服务端在一个事务内：

1. 锁定并消费绑定会话。
2. 创建 `patient`。
3. 创建当前家属的管理员 `care_relation`。
4. 创建设备记录。
5. 追加必要同意记录。
6. 写审计日志。
7. 写资产包生成 Outbox 事件。

接口必须支持 `Idempotency-Key`。同一个键重复请求返回原结果；已被其他请求消费则返回 `409 BINDING_SESSION_USED`。

### 6.3 邀请其他家属

- 只有管理员能生成邀请码。
- 邀请码单次使用、30 分钟有效，并绑定目标 `patient_id` 和成员角色。
- 受邀家属必须使用自己的手机号登录，预览患者昵称、关系和管理员脱敏手机号后确认加入。
- 已有关联时返回原关联，不重复创建患者或关系。
- 不按姓名、照片、手机号或身份证自动判断“同一个患者”。

## 7. 权限设计

后端统一暴露：

```text
authorize_family(user_id, patient_id, capability)
authorize_device(device_id, patient_id, scope)
```

| 权限 | 管理员 | 成员 |
| :--- | :---: | :---: |
| 查看患者/简报 | ✓ | ✓ |
| 创建普通记忆/照片 | ✓ | ✓ |
| 确认本人记忆 | ✓ | ✓ |
| 确认任意成员记忆 | ✓ | — |
| 上传声音样本 | ✓ | 管理员开启能力后可用 |
| 修改患者配置 | ✓ | — |
| 管理同意、成员和设备 | ✓ | — |
| 删除患者全部数据 | ✓ | — |

成员被移除后立即返回 `403 RELATION_INACTIVE`。所有路径中的 `patient_id` 都必须和令牌当前可访问范围匹配。

## 8. 同意与授权

### 8.1 产品级同意类型

```text
ai_companion
non_medical_acknowledgement
private_memory_storage
gaze_feature_collection
acoustic_feature_collection
conversation_history_storage
voice_cloning
photo_animation
```

完成绑定必须同意 AI 陪伴说明、非医疗声明和私有记忆存储。其他能力默认关闭。

### 8.2 强制执行位置

| 操作 | 必须满足 |
| :--- | :--- |
| LLM 对话 | `ai_companion` |
| 保存确认记忆 | `private_memory_storage` |
| 初始化/上报眼动 | `gaze_feature_collection` |
| 计算声学参考特征 | `acoustic_feature_collection` |
| 保存对话原文 | `conversation_history_storage` |
| 处理声音样本 | `voice_cloning` + 素材级授权 |
| 生成照片微动 | `photo_animation` + 素材级授权 |

异步任务在接收时和实际开始执行前各检查一次同意，防止排队期间已撤回授权的任务继续处理。

### 8.3 撤回效果

- 撤回眼动/声学采集后发布新的设备配置版本，患者端 1 分钟内停用对应传感器。
- 撤回对话记录后停止新增存储；历史记录需单独执行删除。
- 撤回声音克隆或照片微动后取消排队任务、停止使用，并删除派生文件。
- 浏览器权限即使仍是“允许”，应用也必须服从服务端最新同意状态。

### 8.4 浏览器权限例外

摄像头和麦克风系统弹窗无法由家属手机远程确认。管理员先在家属端打开业务能力，再由照护者在患者设备的一次性设置页点击系统授权。患者端不显示业务条款，只显示“请家人完成设备设置”。拒绝授权时自动降级，不给患者展示技术错误。

## 9. 患者端状态机

```text
UNENROLLED → COLD_START → CAREGIVER_SETUP → STANDBY
                                           ↕
                                          CHAT
                                           ↓
                                        SOOTHING
```

| 当前状态 | 事件与条件 | 下一状态 |
| :--- | :--- | :--- |
| UNENROLLED | 应用启动 | COLD_START |
| COLD_START | 绑定完成 | CAREGIVER_SETUP |
| CAREGIVER_SETUP | 本地权限完成或跳过 | STANDBY |
| STANDBY | 触屏或语音意图 | CHAT |
| STANDBY | 已授权眼动，注视已标注人物超过 5 秒 | CHAT 人物模式 |
| CHAT | 静默达到 90 秒 | STANDBY |
| CHAT/STANDBY | 17:00–19:30 且命中负面信号 | SOOTHING |
| SOOTHING | 平稳 20 分钟或超过 19:30 | STANDBY |
| 任一已绑定状态 | 设备被撤销 | COLD_START |

日落时间按患者配置的 IANA 时区计算；中国地区默认 `Asia/Shanghai`。设备时间和服务端相差超过 5 分钟时使用服务端偏移。

### 9.1 传感器生命周期

- 只有服务端同意已开启时才延迟初始化传感器。
- 视频帧只在浏览器内存中用于特征提取，用完立即丢弃。
- 环境声学分析只上传数值聚合。
- 对话 ASR 的短时音频和环境声学采集是两条独立路径。
- 权限缺失时停用相应触发，但触屏、待机和基础对话仍可使用。

## 10. 记忆处理

### 10.1 输入限制

- 文本：1–500 个 Unicode 字符。
- 语音：1–30 秒，最大 10 MiB，限定编码格式。
- 照片：最大 15 MiB，JPEG/PNG/WebP，按真实文件签名校验。
- MVP 每条记忆最多一张照片，至少有一种输入。

### 10.2 异步流水线

1. 检查患者访问权限和私有记忆存储同意。
2. 校验文件、扫描安全风险、移除图片元数据并写入私有对象存储。
3. 将短语音转为文本。
4. 拼接患者年代、地区、语言和可选照片上下文。
5. 调用严格 JSON Schema 的抽取模型。
6. 校验字段、置信度范围和不确定字段。
7. 保存抽取结果并通知家属端。

模型可建议照片人物标签，但不能自动创建真实人物或绑定 `persona_id`，人物身份必须由家属确认。

### 10.3 置信度分流

- `< 0.600`：保持 `pending`，必须由家属修改或确认。
- `>= 0.600`：家属端渲染完成后启动 3 秒撤销倒计时，再发出带操作者身份的确认请求。
- 服务端不能只因时间过去而自动确认。
- 成员只能确认自己提交的内容，管理员可确认任意成员内容。
- 更新和确认携带 `revision`，旧版本返回 `409 MEMORY_REVISION_CONFLICT`。

确认后通过 Outbox 触发向量化。患者对话只检索当前 `patient_id` 下已确认且已建立索引的记忆。

## 11. 人物与媒体

家属先创建人物并取得 `persona_id`，再关联照片和声音。显示名可重名。

声音或人物照片处理请求必须附带固定枚举授权声明和条款版本，并生成不可变素材授权记录。下载私有媒体前先鉴权，再签发不超过 5 分钟的临时 URL。

声音选择顺序：

1. 当前人物已有授权且状态为 `ready` 的克隆音色。
2. 当前语言的默认音色。

克隆失败不得中断对话。照片微动失败则回退原图和 CSS 呼吸效果。

## 12. 时代资产包

绑定成功后通过 Outbox 触发资产包任务，缓存键为：

```text
region_code:era:language:generator_version
```

回退顺序：精确缓存 → 30 秒内动态生成 → 年代/语言通用缓存 → 随包 Demo 通用资源。只要任意有效资产包就绪即可激活患者端；后续精确包成功时只替换公共资产，不动私有记忆。

## 13. 对话安全边界

- 中文回复不超过 40 个汉字，英文不超过 30 个单词。
- 禁止直接说患者“记错了”“已经退休”“现在不是那个年代”。
- 被问是否机器人时不得断言自己是真人，可回答“我是陪你聊天的伙伴”。
- 人物模式不能编造记忆库中不存在的共同经历。
- 医疗问题只给出陪伴性边界并建议联系家属或专业人员。
- LLM 超时或两次安全校验失败时使用本地验证疗法话术库。
- TTS 失败时保留大字幕，并用默认音色重试一次。

## 14. 交互事件与每日简报

允许的事件包括会话开始/结束、状态进入、照片注视聚合、对话轮次聚合、主动提及、人物模式、舒缓模式和设备心跳。每种事件使用独立 Schema；`(device_id, event_id)` 唯一保证重试幂等。

每日任务按患者当地日期聚合：

1. 少于 3 个有效历史日时，只显示“正在了解日常状态”，不显示趋势百分比。
2. 使用最近 7 个有效日作为个人基线，不与人群常模比较。
3. 内部权重：注视/互动 40%，回答反应 30%，表达连续性 30%。
4. 共鸣分为 `注视秒数 + 对话轮次×10 + 主动提及×5`，取 Top 3。
5. 生成 1–2 条基于确认记忆的验证疗法沟通建议。
6. 当天无足够数据时明确显示数据不足，不推断状态变差。

家属端响应不包含记忆抽取置信度，也不使用诊断、筛查或疾病风险词汇。

## 15. API 约定

### 15.1 主要接口

| 能力 | 接口 |
| :--- | :--- |
| 请求/验证 OTP | `POST /v1/auth/otp/request`、`POST /v1/auth/otp/verify` |
| 创建绑定会话 | `POST /v1/device/binding-sessions` |
| 首次绑定 | `POST /v1/family/bindings` |
| 创建/接受邀请 | `POST /v1/patients/{id}/invites`、`POST /v1/invites/{code}/accept` |
| 管理同意 | `PUT /v1/patients/{id}/consents/{type}` |
| 创建/确认记忆 | `POST /v1/patients/{id}/memories`、`POST /v1/memories/{id}/confirm` |
| 人物素材 | `POST /v1/patients/{id}/personas/{persona_id}/assets` |
| 设备配置 | `GET /v1/device/config` |
| 设备事件 | `POST /v1/device/events` |
| 每日简报 | `GET /v1/patients/{id}/summaries/{date}` |

### 15.2 通用规则

- 创建、绑定、接受邀请和启动上传支持 `Idempotency-Key`。
- 可修改资源暴露整数 `revision`，冲突返回 409，不使用最后写入覆盖。
- 列表接口使用不透明游标分页。
- 错误结构包含稳定 `code`、本地化 `message`、`request_id` 和 `details`；客户端不得解析 message。
- WebSocket 只发送资源 ID 和状态，不推送完整隐私内容；失败后采用 2 秒起、最大 30 秒的指数轮询。

## 16. 异步任务与可靠性

任务类型包括资产包、记忆抽取、向量化、声音克隆、照片微动、每日简报、媒体删除和患者删除。

业务写入与任务请求通过 Transactional Outbox 在同一事务内提交。可重试错误为超时、429 和 5xx，指数退避加抖动，最多 3 次；格式错误不重试；授权撤回立即取消；删除任务重试到成功或进入可见死信队列。

所有任务处理器必须幂等，并在写结果前检查实体最新状态和同意状态。

## 17. 删除与保留

删除源照片或声音后立即对 API 隐藏，停止使用，并异步删除所有派生克隆、音频或视频。

管理员删除患者后：

- 状态改为 `deletion_pending`。
- 立即撤销家属和设备访问。
- 删除记忆、向量、媒体、对话历史、简报、设备 Token、邀请和缓存。
- 审计只保留删除操作者、不透明患者 ID、动作、时间和结果，不保留内容。

默认保留：OTP 5 分钟，绑定会话 10 分钟，邀请 30 分钟，TTS 缓存 24 小时，失败临时上传 24 小时；已确认记忆与媒体保留至家属删除或患者删除。

## 18. 安全要求

- 只允许 HTTPS/WSS，并限定双端 Origin。
- Token、验证码哈希、邀请码哈希、完整手机号、签名 URL 和对话正文不得写日志。
- 私有媒体静态加密，只通过短期签名 URL 访问。
- 文件按签名而不是扩展名识别，上传后做安全扫描和 EXIF 清理。
- 发给外部 AI Provider 的内容使用不透明患者 ID，并遵循最小必要原则。
- 所有写操作和敏感读操作写结构化审计日志。
- OTP、绑定码、邀请预览、上传、对话和抽取接口必须限流。

## 19. 异常降级

| 异常 | 行为 |
| :--- | :--- |
| OTP 服务不可用 | 返回可重试错误，不泄露账号是否存在 |
| 绑定码过期 | 患者端生成新会话，不创建患者 |
| 资产生成超时 | 使用通用缓存并后台重试 |
| 记忆抽取失败 | 保存草稿，家属可重试，不同步患者端 |
| 低置信度 | 必须家属确认，不进入索引 |
| 声音/微动失败 | 默认音色/静态照片降级 |
| WebSocket 失败 | 退回指数轮询 |
| 传感器权限拒绝 | 停用对应能力，保留触屏和基础对话 |
| 排队期间撤回同意 | 取消任务或丢弃结果并删除派生文件 |
| 设备离线 | 保存配置版本，恢复心跳后同步 |
| LLM 不可用 | 本地验证疗法话术库 |
| 简报数据不足 | 明确提示，不推断认知变化 |

## 20. 测试策略

### 20.1 单元测试

- 角色权限映射和失效关系。
- 同意最新状态、撤回副作用。
- OTP 到期、重试和锁定。
- 绑定、邀请和设备替换状态机。
- 置信度 `0.599` 与 `0.600` 边界。
- 记忆修订冲突和确认人权限。
- 患者端静默计时和日落触发。
- 共鸣分、个人基线、缺失数据重加权。

### 20.2 数据库与接口测试

- 并发下每患者只有一个管理员和一台有效设备。
- 邀请接受幂等，绑定失败整体回滚。
- Outbox 与业务记录同事务提交。
- 任意查询不能跨患者返回记忆、媒体、事件或简报。
- 成员调用管理员接口返回 403。
- 设备 Token 不能调用家属接口，家属 Token 不能上报设备事件。

### 20.3 端到端测试

1. 新家属登录 → 首次绑定 → 必要同意 → 患者端待机。
2. 管理员邀请 → 第二个账号加入 → 两端看到同一 `patient_id`。
3. 成员不能修改同意或解绑。
4. 高置信记忆确认后进入患者对话。
5. 低置信记忆未经明确确认对患者不可见。
6. 人物照片/声音授权后进入人物模式；克隆失败正常降级。
7. 撤回眼动同意后患者端 1 分钟内停用传感器。
8. 浏览器拒绝摄像头/麦克风后患者端仍可使用。
9. “我要去厂里上班”得到非纠错回应。
10. 删除患者后访问失效且内容与派生媒体被清理。
